Nyx Playground Security & User Guide

1. Purpose of the Interactive Playground

The Nyx Playground provides an instant, zero-installation interactive environment for systems programmers, AI engineers, and security auditors worldwide to verify Nyx's language syntax, region memory model, and auto-vectorized SIMD throughput without requiring local toolchain installation.

2. Anti-Exploitation & Air-Gapped Sandbox Architecture

To guarantee that malicious actors cannot exploit the playground or execute unauthorized system commands:

  • Client-Side WebAssembly Isolation: Code evaluation executes entirely inside client-side browser WebAssembly / WebWorkers. No code is executed on backend production servers.
  • Zero Network Egress (Air-Gapped): The virtual runtime has zero access to network sockets, preventing data exfiltration or botnet relaying.
  • Strict Memory Quotas (32MB Ceiling): Execution terminates immediately if an allocation exceeds 32 megabytes, preventing memory exhaustion attacks.
  • Execution Timeout Guard (3.0s Limit): Infinite loops or recursive thread attacks are forcibly terminated after 3,000 milliseconds.
  • Read-Only Virtual Filesystem: Code has no access to the host machine's hard disk, operating system registry, or private credentials.

3. Quick Language Usage Guide

  • Region Allocation: Use region frame { let item = frame.alloc(MyStruct); }. Memory automatically rolls back at the closing brace.
  • SIMD Vectors: Import @nyx/simd and call simd.dot_f32_avx2(v1, v2) to leverage hardware vector registers.
  • Actor Messaging: Use @nyx/mesh ring buffers for lock-free inter-thread communication.

Move Hard Dev to Your Laptop

Take your Nyx code from the in-browser WASM playground directly into a native production workspace on Windows, macOS, or Linux.

Step 1: Scaffolding a Local Project

nyx new my_app --template=std
cd my_app

Step 2: Paste Your Code & Compile Native Binary

# Native bare-metal compilation with full LLVM 18 optimizations
nyx build --release -o bin/app.exe

./bin/app.exe
