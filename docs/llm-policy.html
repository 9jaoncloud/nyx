1. Executive Summary & Core Rationale

Section 1 • Normative Foundation

Nyx is a systems programming language created during the era of large language models. The foundational compiler, runtime, and standard library were architected solo by Simeon Bala in collaboration with advanced AI models.

"The central question in systems engineering is not whether an AI tool was used, but whether the software artifact is mathematically memory-safe, 100% covered by passing tests, reproducible on standard hardware, and accountable to a named human engineer."

While legacy language foundations with decades of pre-AI history attempt to restrict LLM contributions to protect human reviewer bandwidth, Nyx embraces full transparency. We disclose AI involvement as structured metadata, while establishing the strictest verification gate in modern systems software.

2. Deep Dive: Nyx vs. Rust LLM Policies

Comparative Paradigm

In 2026, the Rust Foundation drafted an LLM usage policy designed around human-only legacy assumptions. Below is a structured architectural comparison of why Nyx's model is fundamentally tailored for the modern era:

Core Philosophical Premise Origin-Centric: LLM code generation is restricted/banned in spirit to safeguard human reviewer trust. Verification-Centric: Origin is openly disclosed as metadata; trust is mathematically established through SMT proofs and tests.
Foundational Origin Assumes multi-million line codebase created historically without LLMs. Transparent LLM-era co-creation from Day 0. Disclosed without apology; backed by machine-checked proofs.

3. The 4-Tier Verification Architecture

The Foundation of Trust

Every line of code and every release artifact in the Nyx ecosystem must satisfy one or more tiers of our automated verification pipeline:

TIER 1 • REGRESSION

100% Automated CI Suite

Every commit must pass 100% of unit, integration, and compiler codegen tests. Zero broken tests permitted.

nyx test --all --subsystems
TIER 2 • REPRODUCIBILITY

Deterministic Benchmarks

Every performance claim is pinned to exact CPU/RAM, compiler flags, and reproducible with one CLI command.

nyx bench --provenance
TIER 3 • FORMAL SMT

Jude Formal Proofs

Safety-critical bump allocators and SIMD kernels are verified with pre/post condition SMT contracts via Z3/CVC5.

@verify(ensures: safe_alloc)
TIER 4 • REPLICATION

Turnkey Replication Kits

Containerized kits allow independent external academic researchers and auditors to replicate all published results.

./reproduce_all.sh --audit

4. Permitted, Conditional & Banned Uses

Section 2 • Rules Matrix
✅ §2.1.1 Private Study & Ideation
Asking an LLM to explain compiler internals, region inference passes, or MLIR lowering for your own private study requires no disclosure.
✅ §2.1.2 Private Pre-Submission Code Review
Using an LLM locally to check your branch for subtle edge cases before opening a PR is fully permitted.
✅ §2.1.3 Experimental Prototypes & Benchmarks
PRs marked with [EXPERIMENTAL — DO NOT REVIEW] or on branches starting with experimental/ require no formal disclosure until promoted to stable.
⚠️ §2.3.1 LLM-Assisted Code PRs
Permitted if tagged with llm-assisted, accompanied by complete test coverage, valid provenance headers, and pre-arranged human review.
⚠️ §2.3.2 Dialect Translation (Hausa, Yorùbá, Igbo)
Using LLM translation to bring Nyx docs to indigenous Nigerian languages is allowed with transparent disclosure and native speaker human sign-off.
⚠️ §2.3.4 Review Bots & Automated Scanners
Bots must operate from dedicated bot accounts, be blockable, and can never unilaterally block or merge a PR without human confirmation.
❌ §2.2.1 Impersonating Human Authorship
Posting raw LLM output as your personal analysis, issue comment, or review feedback without disclosure is strictly prohibited.
❌ §2.2.2 Unverified LLM Diagnostics & Documentation
Merging LLM-generated error diagnostics or docs without line-by-line human technical validation is banned.
❌ §2.2.4 Autonomous AI Merge Decisions
An AI model or agent may never serve as the sole approver or gatekeeper for merging code. A named human must sign every commit.
🔨 §2.4.1 Deliberate Provenance Concealment
Intentionally concealing AI assistance, forging provenance headers, or misrepresenting authorial metadata is a serious Code of Conduct violation resulting in contributor bans.
