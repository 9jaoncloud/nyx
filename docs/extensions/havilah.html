Havilah: Linear Capability = Ownership

Unify memory management and capability security into a single linear primitive. An object exists only while its capability token is held—consuming or dropping the token destroys the resource immediately with zero runtime overhead.

File Extension: .hav • Compiler Flag: nyxc --mode=capability • Primitive: Linear Cap<T> • Memory Tax: 0 bytes (Compile-Time)

1. The Core Philosophy of Havilah

Standard Nyx separates memory management (regions) from capability access (security tokens). Havilah unifies them:

"Capability is Ownership. If you hold the capability token, you hold the memory. When you consume or drop the token, the resource is reclaimed immediately."

This eliminates the need for both garbage collection and region boundary inference. Because capabilities are linear by default, they cannot be copied or leaked, creating an unforgeable hardware-enforced sandbox.

2. Syntax & Linear Token Mechanics

In Havilah, every sensitive resource (files, sockets, GPU buffers, motor registers) is accessed via a single-use Cap<T>:

// file: hardware_driver.hav
// Compile with: nyxc --mode=capability hardware_driver.hav -o driver.exe

struct SpiBus;

fn write_oled_display(cap: Cap<SpiBus>, pixels: &[u8]) -> Cap<SpiBus> {
    // Access hardware only through unforgeable linear token
    cap.transmit_raw(pixels);
    
    // Return token to caller; if not returned, SpiBus is immediately shutdown and reclaimed
    cap
}

fn secure_memory_sandbox(entry: Cap<IsolatedSandbox>) {
    let token = entry.allocate_memory(4096);
    token.write_bytes("Confidential biometric payload");
    
    // Dropping 'token' immediately zeros and deallocates the 4096 bytes:
    // drop(token); // Zero residual memory trace in RAM
}

3. Concrete Industrial Use Cases

Use Case 1: Zero-Trust Microkernel OS Device Drivers

Writing bare-metal drivers in Havilah guarantees that unprivileged userland code cannot forge hardware MMIO pointers or access unauthorized registers: 

import kernel.arch.x86_64;
import kernel.capabilities;

struct PciEthernetController {
    mmio_base: u64,
}

// Linear driver function: takes hardware capability, executes DMA transfer, returns capability
pub fn transfer_dma_frame(
    mut cap: Cap<PciEthernetController>,
    packet: &[u8]
) -> Result<Cap<PciEthernetController>, DriverError> {
    // 1. Verify physical ring descriptor alignment
    let desc_ring = cap.map_dma_ring(ring_size: 256)?;

    // 2. Transmit raw frame directly to silicon
    desc_ring.write_buffer(0, packet);
    cap.trigger_interrupt();

    // 3. Return unforgeable capability back to kernel scheduler
    Ok(cap)
}

Use Case 2: Multi-Tenant Cloud Enclaves & Confidential Sandboxes

In confidential computing nodes (AMD SEV-SNP / Intel TDX), data remnants in shared RAM pose severe security risks. Havilah enforces zero residual memory traces upon capability destruction: 

import std.security.enclave;

pub fn execute_confidential_inference(
    enclave_cap: Cap<SecureEnclave>,
    encrypted_weights: &[u8],
    input_vector: &[f32]
) -> OutputPrediction {
    // Allocate isolated encrypted RAM buffer
    let mut weight_buffer = enclave_cap.decrypt_to_confidential_ram(encrypted_weights);
    
    // Run inference inside hardware enclave
    let prediction = enclave_cap.run_neural_forward(&weight_buffer, input_vector);

    // Linear consumption: Explicitly destroy capability token
    // The compiler lowers this to hardware AVX-512 zeroing instructions before releasing page
    drop(weight_buffer);
    drop(enclave_cap);

    prediction
}

Use Case 3: Physical HSM Key Managers & Silicon Token Burning

Cryptographic signature keys stored in Hardware Security Modules (HSMs) must never be cloned or reused across unauthorized transactions: 

import std.crypto.hsm;

struct PrivateSigningKey;

// One-time signature capability: Consumes token upon signing (Single-Use Linear Type)
pub fn sign_interbank_wire(
    single_use_key: Cap<PrivateSigningKey>,
    wire_payload: &[u8]
) -> Ed25519Signature {
    // Hardware sign operation burns the capability token in silicon
    let signature = single_use_key.execute_ecdsa_sign(wire_payload);
    
    // Note: single_use_key is NOT returned; it ceases to exist in the type system
    signature
}

Use Case 4: DO-178C Aerospace Subsystem Fault Isolation

Avionics buses (ARINC 429 / MIL-STD-1553) require strict mathematical partition separation between flight navigation and entertainment modules: 

import avionics.bus.arinc429;

struct NavigationSubsystem;
struct CabinLightingSubsystem;

pub fn process_avionics_tick(
    nav_cap: Cap<NavigationSubsystem>,
    lighting_cap: Cap<CabinLightingSubsystem>
) -> (Cap<NavigationSubsystem>, Cap<CabinLightingSubsystem>) {
    // Navigation capability cannot access cabin lighting memory, and vice-versa
    nav_cap.update_inertial_navigation_unit();
    lighting_cap.dim_cabin_lights(0.8);

    (nav_cap, lighting_cap)
}
