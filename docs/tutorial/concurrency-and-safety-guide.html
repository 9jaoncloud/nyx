Practical Developer Guide

Why These Modules Exist & How to Use Them

A straightforward, plain-English guide explaining why Nyx includes Structured Nurseries, Zero-Copy Isolate Regions, and Formal Contracts, and how to use them in your own real-world apps.

1. Structured Async Nurseries: Why Do We Need Them?

The Real-World Problem:
In Python, Go (go func()), or JavaScript (fetch().then()), if you spawn background tasks, they can run forever in the background even after your main function has finished. If the user navigates away or closes the window, these "ghost tasks" keep consuming CPU and memory, or crash trying to access deleted variables.

How Nyx Solves It (The Safe Room):

A Nursery acts like a parent guardian. All child tasks spawned inside the nursery must complete before the function exits. If any task fails, the nursery cancels sibling tasks automatically.

import std.concurrency;
import std.http;

// Practical Example: Download 3 files in parallel safely
fn download_assets(urls: [String]) {
    let nursery = concurrency::open_nursery();

    for url in urls {
        // Spawns parallel worker bound to this nursery
        concurrency::spawn_task(nursery, || {
            let file = http::get(url);
            file.save_to_disk();
        });
    }

    // This ONE line guarantees all downloads finish before download_assets() returns!
    concurrency::await_nursery(nursery);
    print("All downloads safely finished! Zero memory leaks.");
}

2. Isolate Regions: Why Zero-Copy Transfer Matters

The Real-World Problem:
If Thread A creates a large 50 MB dataset (like 1,000,000 financial orders or an image buffer) and wants to send it to Thread B, traditional languages copy all 50 MB byte-by-byte (memcpy). Copying 50 MB takes ~100 ms and stalls the CPU.

How Nyx Solves It (Zero-Copy Swap):

Thread A creates the dataset inside an Isolate Region. When it sends the region to Thread B, Nyx does not copy the 50 MB. It swaps a single 8-byte pointer atomically. Thread B receives all 50 MB in 5 nanoseconds with zero CPU waste.

import std.concurrency;

fn producer_thread(ch: *void) {
    // 1. Allocate 10 MB isolated region
    let isolate = concurrency::create_isolate(10 * 1024 * 1024);
    
    // 2. Populate 500,000 items inside the isolate
    // ...
    
    // 3. Hand off ownership to consumer thread in 5 nanoseconds
    concurrency::send_isolate(ch, isolate);
    // After sending, Thread A cannot touch 'isolate' anymore (prevents data races!)
}

fn consumer_thread(ch: *void) {
    // 4. Receives full 10 MB instantly without any memcpy copying!
    let isolate = concurrency::recv_isolate(ch);
}

3. Formal Verification: Why Pre/Post Conditions?

The Real-World Problem:
If you are building a simple game and a glitch happens, you restart the game. But if you are building an airplane autopilot, a medical pacemaker, or a high-speed banking engine, a bug could crash an airplane or lose millions of dollars.

How Nyx Solves It (Mathematical Proofs):

With @requires and @ensures, the compiler mathematically checks that inputs and outputs are always valid before your code is ever allowed to run in production.

import std.formal;

// Aerospace / Banking Contract Example
@requires(amount > 0.0 && amount <= balance)  // Must be positive & cannot overdraft
@ensures(result >= 0.0)                         // Account can never end up negative
fn withdraw_money(balance: f64, amount: f64) -> f64 {
    return balance - amount;
}

4. Global Decentralized Package Registry: Why No Central Server?

The Real-World Problem:
Central registries (like npm or PyPI) have suffered catastrophic hacks where malicious actors injected malware into popular libraries. Furthermore, banks, defense agencies, and isolated servers operate in air-gapped networks (without public internet access) and cannot connect to central servers in Silicon Valley.

How Nyx Solves It:

Every Nyx package is cryptographically signed with an Ed25519 author key and hashed with SHA-256. Packages can be synced over local air-gapped networks or decentralized IPFS/Raft nodes, with 100% mathematical proof that no code was altered.

# 1. Sign package with author key
nypm publish @mycorp/crypto-engine --sign key.pem

# 2. Install inside an air-gapped offline environment with strict verification
nypm install @mycorp/crypto-engine --verify-strict
