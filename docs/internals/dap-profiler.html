Debug Adapter Protocol (DAP) & Time-Travel Memory Profiler

Interactive IDE debugging, live breakpoint step-through, and zero-overhead time-travel memory profiling for the Nyx programming language.

1. Debug Adapter Protocol (DAP) Architecture

Nyx provides a native DAP server engine (nyxc/dap_server.nyx & rt_dap.h) communicating with VS Code, Cursor, and DAP-compliant IDEs over JSON-RPC 2.0:

VS Code / IDE ◄── JSON-RPC (DAP Protocol) ──► Nyx DAP Server Engine
                                                      │
                                                      ├── Breakpoint Traps
                                                      ├── Stack Frame Unwinding
                                                      └── Variable Scope Inspection

Supported DAP Requests:

CommandDirectionDescription
initializeClient ➔ ServerNegotiates debugger capabilities and client configuration
setBreakpointsClient ➔ ServerRegisters line and conditional breakpoints in source files
stackTraceClient ➔ ServerReturns call stack frames, source paths, and line numbers
variablesClient ➔ ServerInspects local variables, nominal struct fields, and enums
next / stepInClient ➔ ServerSteps execution forward by line or into function call

2. Time-Travel Memory Profiling

The Nyx runtime includes a high-precision, zero-overhead memory event recorder (rt_profiler.h & std.tooling.profiler) that logs every region creation, bump allocation, and bulk arena reset:

import std.tooling.profiler

let mut prof = profiler.init_profiler()
profiler.record_allocation(&mut prof, 1, 1048576, "matrix_buffer".to_string())

// Scrub timeline back to timestamp t = 1.5s
let snapshot = profiler.scrub_timeline(&prof, 1500000)
std.io.println("Memory Footprint at t=1.5s: " + snapshot.memory_footprint_bytes.to_string() + " Bytes")

3. Visual Perfetto / Chrome Tracing Export

Export memory events directly into standard Chrome Tracing JSON format for interactive visual inspection in chrome://tracing or ui.perfetto.dev:

let trace_json = profiler.export_trace_json(&prof)
// Output: {"traceEvents":[{"name":"rt_arena_alloc","ph":"X","ts":1000,"dur":50,"args":{"bytes":3145728}}]}
